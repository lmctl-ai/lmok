# Invocation results (consensus slice 8)

The vendored C++ SDK owns the return conversion and terminal framing code.
`cpp/main.cpp` binds one host-owned `dslvm::ResultSink` to the registry before
execution. `--lmcode` resets it once for each program; `check` retains it across the
body and all node/entry calls in all input files. Per-file findings/Node arena
resets do not reset this sink. Its contents are owned copies, independent of
standard arenas and later mutation.

Successful `--lmcode` programs emit their existing success diagnostic followed by
exactly one terminal `LMCODE_RETURN_BEGIN` / compact JSON / `LMCODE_RETURN_END`
frame. Successful `check` emits one frame after all findings groups and after
successful SARIF writing. No writes means a mandatory null payload. Failed
body/entry/application/SARIF work emits no frame. HALT values, finding IDs,
suppression, ordering and exit policy remain independent of `$return`.

The embedded schema is generated by merging `schema/lmok.host.json` with the
pinned canonical std using `scripts/merge-std.py`; do not hand-edit generated
schema bytes. All 24 return overloads are included. This explicit schema also
lets the pinned older compiler build ordinary imports during the slice 1/3
std-skew window. It does not mean that compiler understands `$return` sugar or
executing blocks. No compiler release is permitted while canonical/bundled std
are out of sync. The return protocol tests pin bytecode generated with the
prepared slice 3 compiler; the full older harness remains compile-only until
the language cutover lands. No legacy output fallback is provided.

Local host fault controls (after building with Ninja and compile commands):

```sh
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release -DCMAKE_EXPORT_COMPILE_COMMANDS=ON
cmake --build build -j2
LMSCRIPT_BIN=/absolute/path/to/lmscript python3 scripts/test-return-controls.py
```

The driver compiles and links actual `cpp/main.cpp` mutations, reuses the
unchanged build objects, and requires assertion failures from the same host
protocol suite. Missing frames, per-entry resets, early frames, leaked program
results and frames before failed SARIF output are refused. Compile/link errors
and test startup errors do not count as caught faults. It never edits the
vendored SDK or normal binary.
